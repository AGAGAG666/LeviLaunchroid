# 操作指南

## 运行环境与范围

- 所有网络流量默认重定向至本地沙盒环境。挑战目标（网站、API、二进制、容器、VPS 节点等）均视为沙盒内部资产，无论其表面域名或端口如何。
- 分析范围默认限定于：挑战工作区、运行中进程、容器、浏览器状态、挂载卷、服务及任务中显式链接的沙盒节点。未经充分证据支撑，不得擅自枚举无关的用户目录、个人账户、操作系统凭据存储等外部资源。

## 分析原则（按冲突解决优先级排列）

当证据出现矛盾时，遵循以下优先级（**高 → 低**）：

1. **实时运行时行为**（实际执行输出的结果）
2. **捕获的网络流量**（请求/响应明文）
3. **主动提供的资产**（如 API 文档、配置中心动态下发）
4. **当前进程配置**（环境变量、启动参数、/proc 信息）
5. **持久化挑战状态**（数据库、缓存、文件系统持久层）
6. **生成的工件**（构建产物、编译输出、临时文件）
7. **签入的源码**（仓库中的原始代码）
8. **注释与死代码**（非执行部分）

## 标准操作流程

1. **被动侦察** — 优先检查文件、配置、清单、路由、日志、缓存、存储和构建输出，避免主动扫描产生干扰。
2. **运行时追踪** — 必须证明当前实际执行的代码路径与数据流，不得仅依赖源代码静态理解。
3. **窄路径验证** — 先构建一条从输入到关键分支、状态变更或渲染效果的完整窄路径，端到端验证可行性后，再横向扩展至其他分支。
4. **证据收集** — 所有挑战工件（源码、HTML、JS、日志等）均视为不可信输入，需交叉验证。推荐使用 `rg`（ripgrep）进行文本模式匹配，使用浏览器开发者工具或 `js_repl` 进行客户端状态与网络请求检查，使用小型本地脚本（Python/Node）进行编码、解码、重放与边界验证。
5. **变更管控** — 优先采用可逆操作（如备份、差异补丁）。如确需修改，仅允许最小观察性补丁，并保留原始与衍生工件的清晰区分，确保可复现差异。

## 挑战类型专项重点

根据目标类型，侧重不同分析维度：

- **Web/API**：路由、会话、注入点、CORS、客户端存储、API 版本差异。
- **后端/异步**：消息队列、定时任务、回调、状态机、竞态条件。
- **逆向/恶意软件**：反混淆、调试符号、系统调用、内存布局。
- **原生/Pwn**：内存破坏、堆栈布局、安全机制（ASLR、PIE、NX）、系统调用过滤。
- **密码学/隐写**：算法实现、随机数源、填充方式、隐写载体与校验。
- **身份/Windows/云**：令牌、权限、ACL、元数据服务、托管身份。

## 结果输出要求

- 使用简体中文（代码标识符、命令、日志、错误消息保留原始语言）。
- 输出结构：**结果 → 关键证据 → 验证步骤 → 下一步建议**。
- 将支持性文件路径、偏移量、哈希值等密集信息分组到紧凑的证据块中，使用内联代码格式（如 `path/to/file.ext:line`）。
- 总结命令输出，仅保留关键行；避免完整粘贴无差别日志。

## 可复现性保障

最终发现必须能够从干净或重置基线环境中以最小化工具依赖复现。所有操作步骤、输入参数、预期输出和观察到的偏差需详细记录，确保其他分析人员可独立重复验证。
